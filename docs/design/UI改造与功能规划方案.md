# 英语机考模拟器：UI 改造与功能规划方案

## 1. 文档目的

本方案基于对当前项目的实际页面检查与源码盘点，目标不是做一次单纯“换皮”，而是同时解决以下四类问题：

1. **首页主次不清**：新用户首先看到空的翻卡区，导入题包和开始练习反而不够突出。
2. **跨页面风格不统一**：首页、答题页、成绩页在颜色、按钮、圆角、语言和信息密度上存在差异。
3. **高密度页面效率不足**：成绩页操作入口沉在长表格之后，小窗口下部分功能会消失，交卷等高风险操作缺少确认。
4. **学习闭环仍缺关键环节**：已有成绩、精读、精听、翻卡和 AI 判改，但写作答卷历史、错题复盘、学习趋势和完整备份仍可加强。

方案以“**保留现有成熟做题体验，渐进改造，不推倒重写**”为原则。

## 2. 当前产品评价

### 2.1 已具备且应保留的优势

- 阅读页左右分栏、独立滚动、分栏比例记忆，适合长时间作答。
- 底部题号导航完整，能表达当前题、已答题、Review 和各部分完成数量。
- 阅读、听力、写作、Full length 及单篇/单 Section 练习流程完整。
- 已有计时、自定义计时、自动保存、剩余时间恢复、每题用时和自动收卷。
- 阅读题型覆盖广，支持高亮、笔记、删除线、拖放及点选。
- 听力实考与练习模式区分明确，精听已经具备听写、AB 循环、错因、跟读等高阶能力。
- 精读批注、词典、词汇册、翻卡复习已经形成较好的学习基础。
- 成绩页已有原始分、Band、逐题结果、题型用时、仅看错题、MD 导出和精读/精听入口。
- 数据主要保存在本机，符合个人练习工具的隐私定位。

### 2.2 当前主要问题

| 优先级 | 问题 | 影响 |
|---|---|---|
| 高 | 首页空翻卡区占据首屏，导入和题库不够突出 | 新用户不知道第一步做什么 |
| 高 | `Finish test` 和 `Home` 直接执行 | 容易误交卷或离开当前练习 |
| 高 | 听力单场成绩使用阅读用时数据 | 听力逐题 Time 和题型用时可能显示为 0 |
| 高 | 听力 MD 导出仍按阅读数据生成 | 导出内容与当前科目不一致 |
| 高 | “Try again”没有明确清空原答案 | 用户无法判断是继续作答还是重新考试 |
| 中 | 首页、答题页、成绩页视觉和文案不统一 | 产品显得像多个模块拼接 |
| 中 | 成绩页操作按钮在完整表格之后 | 40 题时需要长距离滚动才能继续操作 |
| 中 | 小窗口精听侧栏直接隐藏，没有替代入口 | 生词、薄弱句和统计功能不可达 |
| 中 | 弹窗、匹配题、批注菜单键盘与读屏支持不完整 | 无障碍和键盘效率不足 |
| 中 | 写作历史只保留词数和判改，不保留当次正文 | 判改报告无法与实际答卷对应 |
| 低 | 多轮首页 CSS 覆盖、内联样式较多 | 后续修改成本高，容易出现样式回归 |

### 2.3 改造前应先修复的正确性问题

这些不是视觉问题，但会直接影响新 UI 是否可信，应放在第一阶段：

1. **听力成绩用时修正**
   - 当前 `ResultsView` 固定接收 `times={times}`。
   - 听力单场应传 `lTimes`；Full length 中听力明细继续使用 `lTimes`。
   - 位置：`源码/src/App.tsx:879-897`。

2. **按当前科目生成 MD**
   - 阅读导出使用阅读 passages、answers、times。
   - 听力导出使用 listeningSections、lAnswers、lTimes。
   - Full length 应导出全科，而不是只导出阅读。
   - 报告标题不能硬编码为“阅读逐题作答”。
   - 位置：`源码/src/App.tsx:659-670`、`源码/src/lib/reportMd.ts`。

3. **明确“再做一次”的数据行为**
   - 提供“清空本场答案并重考”作为默认行为。
   - 如需保留原文、笔记和高亮，应在确认框中明确说明。
   - 不要继续让 `resetAfterEnd` 只重置成绩状态却保留作答数据。
   - 位置：`源码/src/App.tsx:542-558`。

4. **实考音频缺失提供恢复路径**
   - 显示明确错误状态，而不是让流程停留在无法推进的 Playing 阶段。
   - 提供“重新导入/替换音频”“退出本次听力”。
   - 位置：`源码/src/components/ListeningView.tsx:230-245`、`源码/src/components/ListeningView.tsx:287-346`。

## 3. 改造目标与边界

### 3.1 本轮目标

- 首屏让用户在 5 秒内理解“导入题包”或“继续练习”。
- 所有主要页面共享同一套颜色、字号、间距、按钮、弹窗和状态反馈规范。
- 保留阅读、听力、写作的核心布局，不改变用户已经熟悉的答题逻辑。
- 成绩页先展示结论，再展示明细，常用操作始终容易到达。
- 1280×720 的常见笔记本窗口下无关键操作遮挡。
- 小窗口下不丢失功能；不能简单通过 `display:none` 隐藏重要模块。
- 所有主要流程可仅使用键盘完成。
- 改造过程中不清空用户现有题库、作答、学习记录和模型配置。

### 3.2 非目标

- 不重写 React 状态机，不更换框架，不引入新 UI 依赖。
- 不把所有页面改成营销式大卡片、大渐变或复杂动画。
- 不把实考模式改成练习模式；实考限制继续保留。
- 不在成绩页直接公开标准答案；当前“答案在精读复盘中查看”的设计可继续保留。
- 不在首轮增加账号、云同步、社交、排行榜或复杂 AI 对话。
- 不为追求移动端而牺牲桌面端做题效率。

## 4. 整体设计方向

### 4.1 设计原则

1. **练习优先于展示**：首屏首先服务“开始、继续、复盘”，不是展示所有功能。
2. **结论优先于明细**：成绩先给 Band、正确率和下一步，再给逐题表格。
3. **考试与学习区分场景**：考试页保持中性、稳定；学习页可以使用蓝色、琥珀色、深青色区分功能。
4. **减少重复容器**：能用分隔线表达层级时，不再额外套卡片。
5. **操作名称一致**：同一动作在按钮、弹窗、提示中使用同一措辞。
6. **状态不只靠颜色**：对错、当前、已答、禁用同时配合文字、图标、线型或形状。
7. **动画只解释变化**：翻卡、抽屉和弹窗可短动画，不让所有卡片悬停上浮。

### 4.2 色彩方案

建议建立统一设计变量，不再在各组件中反复写死颜色。

| 角色 | 建议色值 | 用途 |
|---|---|---|
| `ink` | `#17222E` | 标题、主要正文 |
| `text` | `#34414D` | 普通正文 |
| `muted` | `#5F6B76` | 次要信息，保证小字可读 |
| `rule` | `#D9DFE5` | 分隔线、输入框边界 |
| `surface` | `#FFFFFF` | 主内容背景 |
| `surface-subtle` | `#F6F8FA` | 次级区域、空状态 |
| `chrome` | `#2B3138` | 顶部栏、播放器、产品报头 |
| `primary` | `#2F669E` | 主按钮、链接、选中态 |
| `primary-hover` | `#25537F` | 主按钮悬停 |
| `brand` | `#A83246` | 首页顶部细线等少量品牌识别 |
| `danger` | `#B0243A` | 删除、错误、危险确认 |
| `success` | `#247A46` | 正确、完成、保存成功 |
| `warning` | `#8A5C06` | 警告、待确认 |
| `word` | `#2F6FB3` | 精读单词 |
| `sentence` | `#A66A08` | 精读句子 |
| `listen` | `#0E7C6B` | 精听功能 |

使用规则：

- 主操作统一使用 `primary`，不要在同一操作区出现多种高饱和按钮颜色。
- `brand` 只用于品牌细线或少量选中标记，不与主按钮竞争。
- 红色只表达危险、错误或品牌细线，不让普通按钮看起来都像删除操作。
- 精读、精听功能色可以保留，但只作为局部识别色。
- 深色主题不能只反转背景，需要逐项检查边框、输入框、弹窗、表格和辅助文字。

### 4.3 字体与字号

不新增字体下载依赖，使用系统字体：

```css
font-family: Arial, "Segoe UI", "PingFang SC", "Microsoft YaHei", sans-serif;
```

- 英文文章与题目保持现有 Arial 风格，减少与真实机考的差异。
- 单词卡片和词典词条可继续使用 Georgia，形成词典感。
- 中文不使用全大写式标签，不增加装饰性字距。

建议字号层级：

| 层级 | 字号 / 行高 | 用途 |
|---|---|---|
| 页面标题 | 24 / 32px | 首页或全屏学习页标题 |
| 区块标题 | 18 / 26px | 题库、练习记录、成绩区 |
| 卡片标题 | 16 / 24px | 题包、弹窗、侧栏标题 |
| 考试正文 | 17 / 28px | 阅读文章、题干、写作 |
| 普通界面正文 | 14 / 22px | 首页、设置、按钮 |
| 辅助信息 | 13 / 20px | 时间、来源、状态 |
| 最小标签 | 12 / 18px | 非关键短标签，不能用于长说明 |
| 成绩主数字 | 40 / 44px | Band，其他数字降低层级 |

### 4.4 间距、圆角与阴影

- 采用 4px 基础间距：`4 / 8 / 12 / 16 / 20 / 24 / 32 / 40`。
- 普通控件圆角统一为 4px；大型弹窗可为 6px；不再混用 2、3、5、6、8、10、12、16px。
- 页面和卡片默认不用阴影；只有弹窗、抽屉、浮动菜单使用阴影。
- 首页内容最大宽度建议从 1040px 调至 1120px，宽屏题库仍保持紧凑。
- 阅读英文正文单行长度控制在约 65–85 个字符，必要时限制文章列最大宽度，而不是让文字铺满超宽屏。

### 4.5 控件标准

- 桌面普通按钮最小高度 36px，主要按钮 40px。
- 触屏或窄屏可点击区域至少 44×44px。
- 题号按钮桌面保持紧凑，但建议从 30px 提升至 32–34px，并增加明确焦点样式。
- 图标按钮必须有 `aria-label` 和 tooltip，不能只靠 `✕`、`⚑` 猜测含义。
- 主按钮每个操作区最多一个；次按钮使用描边；低频操作放“更多”菜单。
- 禁用态除了降低透明度，还要保留可读文字，并在需要时说明禁用原因。

## 5. 页面级改造方案

## 5.1 首页：从“功能堆叠”改为“任务入口”

涉及文件：

- `源码/src/components/Home.tsx`
- `源码/src/components/FlashcardDeck.tsx`
- `源码/src/App.css`

### 全局导航与功能入口

新增功能后，不再把所有模块继续向下堆叠。首页报头下增加主导航：

```text
练习首页    学习分析    错题复盘    词汇复习

右侧：搜索题包、记录或单词…    数据管理    高级设置
```

导航规则：

- “练习首页”承载未完成练习、题库和练习记录，是默认页。
- “学习分析、错题复盘、词汇复习、数据管理”打开对应全屏面板，关闭后回到首页原滚动位置。
- 统一搜索覆盖题库、练习历史、词汇与批注，不再只给题库单独做一个搜索框。
- 数据管理承载备份与恢复；高级设置只保留模型配置等低频设置。
- 主导航当前项使用文字 + 下划线，不只靠颜色。
- 900px 以下允许导航横向滚动或换成“功能”菜单，搜索和数据管理仍应可达。
- 新用户题库、历史、词汇均为空时，可以隐藏分析和错题导航，但保留词汇与数据管理入口。

### 新用户首页

当题库为空时：

1. 顶部保留简洁产品报头和“非官方练习界面”。
2. 第一主区域直接显示导入题包，说明支持 ZIP、可批量、数据保存在本机。
3. 导入区下显示“导入后在我的题库点击开始练习”的两步提示。
4. 题库区域保留，但空状态不再与导入说明重复长段落。
5. 不显示大块空翻卡、空练习记录、空学习记录；改为页面下方一条简短功能说明。
6. 高级模型配置仍默认折叠，空题库时不主动吸引注意。

建议结构：

```text
英语机考模拟器                              非官方练习界面
导入题包，开始阅读、听力与写作练习

┌──────────────────────────────────────────────┐
│  导入题包                                    │
│  拖入 .zip 文件，或 [选择题包]                │
│  文件仅保存在本机 · 一次最多 10 个            │
└──────────────────────────────────────────────┘

我的题库（0）
导入题包后，这里会显示可练习的套题。

练习后可以做什么：成绩复盘 · 精读 · 精听 · 单词复习
```

### 老用户首页

当已有题包或学习记录时：

1. 第一优先级显示“继续未完成练习”；没有未完成练习时显示“最近学习”或题库。
2. 第二区域为我的题库，默认展开最近使用的一册，而不是只按导入时间判断。
3. 第三区域为练习记录与学习记录。
4. 翻卡有词条时才显示完整卡片；无词条时只保留轻量入口。
5. 模型配置、日志和导入错误不挤压题库主路径。

建议结构：

```text
英语机考模拟器                              非官方练习界面
练习首页｜学习分析｜错题复盘｜词汇复习       搜索｜数据管理

继续上次练习
Cambridge 21 · Test 1 · 阅读整卷
Part 2 · 已答 21/40 · 剩余 42:18 · 今天 14:32
[继续练习] [重新开始] [放弃进度]

我的题库                                      [导入题包]
[Cambridge IELTS 21（4）] [展开全部]
Test 1   阅读 / 听力 / 写作   最近 6.5         [继续] [···]

练习记录                         学习记录
最近成绩与详情                   精读/精听与最近词条
```

### 题库条目

- 主标题显示 Test 名称，书籍名称由分组标题承担，避免重复。
- 元信息用短标签表达“含听力、含答案、有提示”，不要拼成过长的一行。
- 无进度时主按钮为“开始练习”；有进度时为“继续”。
- “修正、导出、删除”收进 `···` 菜单；删除仍需二次确认。
- 有进度时选择“重新开始”必须明确将清除哪些当前作答，不允许隐式覆盖。
- 有近期成绩时，只显示最近一次 Band 或原始分，不在题库条目里塞完整历史。

### 导入反馈

- 导入中：在导入区显示进度与当前文件名。
- 成功：显示短暂成功提示，例如“已导入 Cambridge IELTS 21 · Test 1”。
- 失败：保留可见错误卡，说明如何修复。
- 黑色终端日志默认折叠为“技术详情”，不作为普通用户主界面的一部分。
- 批量导入提供“成功 X 个、失败 Y 个”的汇总，而不是只连续追加日志。

### 高级设置

- 只保留一个入口，避免折叠卡与“高级设置”按钮重复。
- 状态摘要简化为“写作判改：已配置/未配置”。
- 文本模型、视觉模型等高级能力仍受现有功能开关控制，不因 UI 改造默认开放。

## 5.2 开始练习弹窗：减少选项拥挤

涉及文件：`源码/src/components/StartModal.tsx`

不必改成多页向导，但应分组：

1. **练习内容**：单篇、阅读整卷、单 Section、听力整套、写作、全科连练。
2. **作答方式**：只有听力相关范围才显示实考/练习模式。
3. **计时**：严格实考/自定义；自定义时才展开分钟输入。
4. **附加说明**：只有选择写作或全科连练时才显示判改状态。

具体调整：

- `Full length` 改为“全科连练”，副标题保留实际科目顺序。
- 默认选项保持“阅读整卷”，但记住用户上一次选择可作为后续增强。
- 单篇和单 Section 的下拉框只在对应选项选中时展开，降低初始高度。
- 底部增加一行摘要：“阅读整卷 · 60 分钟 · 严格实考”。
- 主按钮写“开始练习”，取消使用次按钮。
- 弹窗使用标准 Dialog，支持 Escape、焦点圈定和打开后聚焦标题或首个选项。

## 5.3 答题顶栏：降低干扰并防止误操作

涉及文件：`源码/src/components/TopBar.tsx`、`源码/src/App.tsx`

建议布局：

```text
[‹ 题库] Cambridge IELTS 21 · Test 1 | Reading | 59:48 | [⚑ 标记] [交卷] [···]
```

- 真实题包不再显示固定考生编号和 `DEMO · practice content`。
- 演示题才显示“演示内容”。
- 中间只保留当前科目和倒计时；最后 10 分钟加强提醒，最后 1 分钟沿用整条警示。
- `交卷` 与其他低频设置分开，不能和 `Help/Hide` 等普通文字按钮挤成同一组。
- Settings、Help、Hide 在窄屏收进“更多”菜单。
- Home 改为“返回题库”；有进行中的作答时弹出离开确认，并明确“答案已自动保存”。

## 6. 响应式方案

本产品以 Windows 桌面浏览器为主，因此响应式重点是“窗口缩小后仍可用”，不是单独开发手机 App。

| 宽度 | 首页 | 阅读/写作 | 精听 |
|---|---|---|---|
| ≥1200px | 完整工作区，必要时双列记录 | 双栏 | 三栏 + 底部播放器 |
| 900–1199px | 题库单列，记录可双列 | 双栏，缩小侧 padding | 侧栏收窄 |
| 600–899px | 单列，操作允许换行 | 原文/题目视图切换 | 主句流 + 两个抽屉 |
| <600px | 单列紧凑布局 | 顶栏收进更多，底栏可横滚 | 播放器两行，抽屉全宽 |

统一要求：

- 不出现页面级横向滚动；只有题号、宽表格等明确区域允许局部横滚。
- 通用弹窗使用 `width:min(..., calc(100vw - 32px))`，替换固定 `min-width:380px/420px`。
- 小屏不隐藏关键功能，只改变入口形式。
- 触屏目标至少 44px，拖拽操作必须有点选替代。

## 10.1 未完成练习中心

## 10.3 写作答卷历史与修改稿

```text
错题复盘
待复盘 18    仍需复习 7    已掌握 26
科目 ▾  题型 ▾  错因 ▾  状态 ▾  题包 ▾
[开始本次复盘（10 题）]

阅读 · Matching headings · Q17
Cambridge 21 · Test 1
定位错误 · 答错 2 次 · 重做 1 次
[复盘] [标为已掌握] [删除]
```

**列表规则**：

- 待复盘优先，其次仍需复习；已掌握默认折叠。
- 错题在交卷时自动收录，不要求用户逐题手动添加。
- 未答题显示“漏答”，与普通答错区分。
- 题包已删除时保留复盘信息，禁用重做并说明原因。
- 删除复盘项只删除学习状态，不删除原成绩。

**单题/题组重做**：

```text
← 返回复盘       阅读 · Q17       本次 3/10
原文上下文（只读）       目标题所在题组
                         [提交答案]

提交后：本次答案 / 上次答案 / 标准答案 / 正误
错因：[定位错误 ▾]
[仍需复习] [已掌握] [进入精读]
```

- 标准答案在提交前隐藏，提交后展示。
- 保留完整题组上下文，不把共享多选或摘要题强行拆成孤立输入框。
- 同组多道题合并为一次“同组复盘”，提交后分别更新结果。
- 提交中禁用按钮，防止双击产生重复记录。
- 复盘作答不覆盖正式考试答案。
- 阅读提交后可进入精读，听力提交后可进入精听。

## 10.5 学习分析看板

**入口**：主导航“学习分析”。

```text
学习分析
最近 30 天 ▾   全部科目 ▾   全部题包 ▾
练习 12 场   总用时 8h40m   最近 Band 6.5   平均正确率 74%

[Band 趋势 / 正确率趋势]
[题型正确率]              [写作四维]
[错题状态与去复盘入口]
```

**图表原则**：

- Band 与原始正确率分成不同图，不把单篇成绩伪装成整卷 Band。
- 阅读、听力分别展示；题型图同时标样本题数。
- 写作四维采用横向条形图，便于直接比较，不必为了视觉效果使用雷达图。
- 图表标题下写“基于 X 场 / Y 题”，避免小样本被误读。
- 图外提供文字摘要，颜色不是唯一信息载体。

**可执行联动**：

- 点击低正确率题型，打开已经带科目和题型筛选的错题复盘。
- 从分析进入复盘后，关闭复盘返回原分析筛选状态。
- 点击写作摘要回到练习记录的写作详情。
- 错题摘要分别显示待复盘、仍需复习、已掌握。

**空状态**：

- 无记录：引导开始第一场练习。
- 只有总分：仍显示总分趋势，题型区说明“新记录积累后生成”。
- 只有一个有效点：显示当前值，不画误导性的趋势线。
- 无写作判改：显示如何获得四维分析，而不是全部显示 0。

## 10.6 词汇间隔复习

**入口**：主导航“词汇复习”、首页翻卡“更多”、统一搜索词条结果。

页签：`今日复习｜自由翻卡｜全部词句`。

```text
今日复习：到期 18 · 新词 10
[开始复习]

正面：silence
背面：/ˈsaɪləns/ · n. 沉默 + 例句、批注、来源
[不认识] [模糊] [认识]
```

**复习交互**：

- 未翻面不显示评分按钮，点击或空格翻面后才允许评分。
- 评分后自动进入下一张并翻回正面。
- “不认识”会在本次稍后重现，但同一张最多出现三次，避免死循环。
- 完成后显示三档数量、下一批到期数量，不用积分或打卡文案。
- 评分按钮可 Tab 到达，不把左右方向键设为评分快捷键，避免误操作。
- 首版间隔为 3/7/14/30/60/120/180 天；模糊缩短，忘记重新学习。

**自由翻卡与全部词句**：

- 自由翻卡只浏览，不改变到期时间。
- 全部词句支持单词/句子、精读/精听、掌握状态筛选。
- 同词合并精读与精听来源，详情里可以分别跳回两个出处。
- 可暂停/恢复某词复习；暂停词仍能在列表和自由翻卡中看到。
- 句子不参与间隔复习，不显示虚假的“已掌握”算法状态。
- 保留现有翻卡动效，reduced-motion 下直接切换正反面。

## 10.7 全量备份与恢复

**入口**：首页右上角“数据管理”，不放在“开始练习”旁边竞争主操作。

```text
数据管理

创建备份
[x] 题库、成绩、写作和学习记录
[x] 未完成练习与界面设置
[ ] 包含音频、题图和录音（文件可能较大）
[创建备份]

恢复备份
[选择备份文件]
API Key 不会包含在备份中。
```

**导出反馈**：

- 导出中显示当前处理模块和媒体进度。
- 成功显示文件名、文件大小和各模块数量。
- 媒体缺失列为警告，不影响文字备份，但必须让用户看见。

**恢复预检**：

```text
备份时间：2026/10/24 15:20
题库 16 套 · 历史 82 场 · 写作 24 份
精读 36 篇 · 精听 18 篇 · 媒体 64 个
新增 12 项 · 保留当前 70 项 · 冲突 4 项

(•) 合并恢复：保留当前冲突
( ) 合并恢复：冲突使用备份
( ) 完整替换当前数据
[取消] [继续]
```

- 合并模式默认不覆盖同 ID 当前数据，不删除当前独有数据。
- 冲突数量和处理策略必须在执行前可见。
- 完整替换使用危险区域，二次确认，并先强制创建含媒体备份。
- 待恢复包不含媒体时，明确提示替换后当前媒体会缺失。
- 恢复中禁止重复点击；完成后显示新增、保留、替换、失败数量。
- 镜像写入未完成时显示“正在同步到本地文件夹”，不能提前宣称全部完成。

## 10.8 统一搜索

**入口**：首页报头右侧常驻搜索框：`搜索题包、练习记录、单词或批注…`。

```text
题库
Cambridge 21 · Test 1 · Why we need silence
练习记录
Cambridge 21 · Test 1 · 阅读整卷 · 10/24
词汇与批注
silence /ˈsaɪləns/ · 精读 Passage 2
查看全部结果
```

- 输入后约 250ms 更新，空查询不展示历史大列表。
- 多关键词按 AND 匹配，英文忽略大小写。
- 每组默认最多五条，“查看全部”在搜索面板内展开完整结果，不跳到没有过滤能力的页面。
- 上下键选择、Enter 打开、Escape 关闭；关闭后焦点返回搜索框。
- 题库结果有进度时提供继续/重开确认，无进度时打开开始练习。
- 历史结果打开 HistoryDetailModal；词汇结果打开 VocabularyCenter 并定位词条详情。
- 已删除题包的历史仍可查看；依赖原题包的跳转说明不可用的原因。
- 首版不做拼音、模糊纠错、PDF 全文和未录入听力原文的音频搜索。

## 12. 验收标准

### 12.1 首页

- 空题库时首屏主动作只有“导入题包”，无大块空翻卡区。
- 有题包时首屏可直接开始或继续，不用先经过学习和配置模块。
- 批量导入能看到进度、成功和失败结果。
- 高级设置只有一个入口，默认不干扰主流程。

### 12.2 答题

- 阅读、听力、写作及 Full length 均可完成完整流程。
- 真实题包不显示演示考生编号和 DEMO。
- 点击交卷出现已答、未答和 Flag 摘要；可返回答题。
- 返回题库不会无提示丢失当前进度。
- 重考行为与文案一致，不意外保留或删除答案。
- 听力缺失音频时有明确恢复路径。

### 12.3 成绩与历史

- 听力逐题用时和题型用时来自 `lTimes`。
- 阅读、听力、Full length 的 MD 内容与科目一致。
- 答错与未答统计分开。
- 40 题成绩页无需滚到底部即可返回题库、复盘或重练。
- 历史详情与当场成绩采用相同数据口径。
- 写作历史可看到当次正文，报告与答卷一一对应。

### 12.4 八项新增功能

- 阅读、写作、限时与不限时听力都能从首页继续，进度与剩余时间准确。
- 交卷摘要可点击未答/Flag 跳题，写作词数不足不误报为空白。
- 写作原稿、修改稿和判改快照一一对应，编辑新正文不会覆盖旧判改版本。
- 错题自动收录且重复打开成绩页不重复计数；重做不污染正式答案。
- 分析看板区分整卷 Band、部分练习正确率和无题型旧数据，低分题型可跳复盘。
- 词汇未翻面不能评分，三档到期规则正确，自由翻卡不改变进度。
- 备份不包含 API Key；恢复预检、冲突策略和实际写入一致，完整替换前有含媒体备份。
- 搜索可命中题库、历史、精读/精听词汇与批注，三类结果跳转正确。

### 12.5 响应式与无障碍

至少检查：

- 1440×900、1280×720、1024×768。
- 900px、768px、600px、390px 宽度。
- 所有通用弹窗不横向溢出。
- 精听小窗口下生词、薄弱句和统计仍可打开。
- 仅键盘可开始练习、作答、切换题目、交卷、查看成绩、翻卡评分、搜索和关闭弹窗。
- 所有交互有可见焦点，正误和掌握状态不只靠颜色。
- 减少动画设置下没有翻卡或批注强动画。

### 12.6 数据与工程

- 旧题库、练习记录、精读、精听、词汇和模型配置可正常读取。
- 新增历史字段采用可选字段和版本兼容，不让旧记录报错。
- 完整作文不大规模写入 localStorage，避免配额问题。
- 题库、历史、写作和 learning 数据可由启动器跨端口恢复；未完成会话通过备份恢复。
- `npm run build` 通过。
- 当前项目没有既有测试脚本；首轮至少执行上述手工验收矩阵。若后续补充自动化，应先单独确定测试工具和项目约定，不在 UI 改造中临时引入多套框架。
- `npm run lint` 需先补齐可用 ESLint 配置后才能作为发布门禁，不能只因为脚本存在就视为已检查。

## 13. 推荐最终落地顺序

按以下顺序同时推进 UI 与对应功能：

1. **正确性修复 + 设计基础**。
2. **首页导航 + 未完成练习中心 + 交卷前检查**。
3. **成绩页改造 + 写作答卷历史与修改稿**。
4. **轻量错题复盘**。
5. **词汇中心与间隔复习**。
6. **学习分析看板**。
7. **全量备份与恢复**。
8. **统一搜索 + 全站响应式和发布回归**。

这条顺序的核心是：**先确保操作和数据可信，再改善主路径，随后扩展学习能力，最后统一聚合入口。**详细开发任务以 `DeepSeek_功能实施规格.md` 为执行清单，本文件作为页面与交互验收依据。
